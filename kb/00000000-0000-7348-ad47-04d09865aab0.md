# KINGSMetaL

I want documentation that people can read, programs can navigate, and neither needs a particular application to keep. KINGSMetaL is the small convention I use to give ordinary Markdown documents a consistent identity and enough structure to form a knowledge base.

The name is a mnemonic for the order of fields in YAML frontmatter: **K**ind, **I**d, **N**ame, **G**ist, **S**copes, **Meta**, **L**inks. The prose follows the closing `---` as normal Markdown.

## The fields

- **kind** says what sort of document this is. A vocabulary belongs to the knowledge base using it; the format does not prescribe every kind.
- **id** is the document's permanent identity, a UUIDv7. Titles, names and storage locations can change without changing what document a reference identifies.
- **name** is a short, human-friendly name. It need not carry the burden of permanent identity. Within a knowledge base, the pair of kind and name should identify one document.
- **gist** is a compact statement of what the document says. It should carry enough meaning to decide whether to read the body, rather than merely repeat the title.
- **scopes** identifies the repositories or other subjects the document applies to, when that context is useful.
- **meta** holds structured fields specific to the kind or application.
- **links** records relationships to other documents. Each entry names a document and gives the relationship a `rel`, so a reader or tool can tell why the link exists.

The first four fields identify and summarize the document. Omit optional fields when they have nothing to say. These public philosophy documents generally need neither scopes nor meta.

The field order is a reading convention: familiar placement makes documents easier to scan and their diffs easier to review. YAML parsers address keys by name, so reordering fields does not change their meaning. Use valid YAML, two-space indentation, and quote prose when writing by hand if punctuation could be misread.

## A document is a file

Store a document as `kb/<id>.md`. Its frontmatter carries the identity; the filename makes finding it by identity straightforward. Its H1 is its display title, free to use capitalization such as KINGSMetaL without changing `name: kingsmetal`.
